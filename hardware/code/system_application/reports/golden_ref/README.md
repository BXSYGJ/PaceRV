# golden_ref: dtype-correct per-layer golden references

Generated by `scripts/gen_golden_refs.py` from the authoritative golden
model (`scripts/golden_pipeline.py`: `run_mel_pipeline` -> `npu_forward`).

This directory is **not** the frozen archive `scripts/outputs/golden/`.
That archive keeps the first golden run and is intentionally stale:

| archive file | problem |
| --- | --- |
| `sine_440_full_feat.npy` | int8, all-zero (the current pipeline emits uint8 0..255) |
| `sine_440_full_conv1.npy` | derived from the stale feat, no conv2/3/4 |
| `sine_440_full_fc2.npy` | u8 container (`out_u8`), not the int32 `out_u8 - zp_out` wire value |
| `sine_440_full_probs.npy` | float64, not Q0.16 |

Using those files as `compare_layers.py --ref` produces false
differences. Regenerate instead of editing the archive; the generator
refuses an output root inside `scripts/outputs/golden/`.

## Regenerate

```powershell
cd instrec_fpga
python scripts/gen_golden_refs.py                 # archive stems + tests/fixtures wavs
python scripts/gen_golden_refs.py --stem sine_440_full
python scripts/gen_golden_refs.py --wav path\to\track.wav
```

Each run rewrites `<out-root>/<stem>/` (default `reports/golden_ref/`).
The wav is looked up as `<stem>.wav` in `tests/fixtures/` and
`InstRec/data/demo/irmas_test/` (the fixture set plus the real irmas
samples); `--wav` bypasses the search.

## Files per stem

16 `.npy` files + `stats.json` + `manifest.json`.

| file | dtype | shape | domain / meaning | wire layer |
| --- | --- | --- | --- | --- |
| `feat.npy` | uint8 | (64, 258) | Mel feature, quint8 container, `zp_in = 49` | 0x00 |
| `conv1.npy` | uint8 | (48, 64, 258) | conv1 output scale, `zp_out = 0` | 0x01 |
| `conv2.npy` | uint8 | (96, 32, 129) | conv2 output scale, `zp_out = 0` | 0x02 |
| `conv3.npy` | uint8 | (192, 16, 64) | conv3 output scale, `zp_out = 0` | 0x03 |
| `conv4.npy` | uint8 | (256, 8, 32) | conv4 output scale, `zp_out = 0` | 0x04 |
| `pool1.npy` | uint8 | (48, 32, 129) | `maxpool2x2_floor` | - |
| `pool2.npy` | uint8 | (96, 16, 64) | `maxpool2x2_floor` | - |
| `pool3.npy` | uint8 | (192, 8, 32) | `maxpool2x2_floor` | - |
| `pool4.npy` | uint8 | (256, 4, 16) | `maxpool2x2_floor` | - |
| `gap.npy` | int32 | (256,) | `round_half_even(sum >> 6)`, fc1 input scale | - |
| `fc1.npy` | uint8 | (128,) | fc1 output (LinearReLU rail), `zp_out = 0` | 0x05 |
| `fc2_logits.npy` | int32 | (8,) | signed container `fc2_u8 - zp_out(57)` | 0x06 |
| `probs.npy` | uint16 | (8,) | Q0.16 probabilities (0..65535) | 0x07* |
| `probs_float.npy` | float64 | (8,) | `probs.npy / 65536`, human-readable only | - |
| `probs_u8_percent.npy` | uint8 | (8,) | `compare_layers` `percent` encoding (0..100) | 0x07 |
| `probs_u8_q0_8.npy` | uint8 | (8,) | `compare_layers` `q0.8` encoding (Q0.16 >> 8) | 0x07 |
| `stats.json` | - | - | per-file min/max/n_unique, top1, probs sum, percent | - |
| `manifest.json` | - | - | dtype/shape/sha256/source/wire id/contract layer per file | - |

`*` `probs.npy` carries Q0.16 but the UART PROBS layer is 8 x u8, so it
must NOT be used directly as a `--ref` for 0x07 (uint16 -> uint8 would
wrap). Use `probs_u8_percent.npy` or `probs_u8_q0_8.npy` instead.

`manifest.json` `files.<stage>` also records `source` (the exact
producing function) and `contract_layer` / `contract_layer_id`.

## Two different layer_id numbering schemes

Do not mix them up:

* **wire / UART layer_id** (`uart_frames.LAYER_SHAPES`, used by
  `compare_layers.py --ref`): `0 = MEL_Q8_8`, `1..4 = CONV1..CONV4`,
  `5 = FC1`, `6 = FC2_LOGITS`, `7 = PROBS`, `8 = STATS` (no reference).
  Pools and the GAP vector have no wire layer and no `--ref` slot.
* **`scripts/outputs/layer_contract.json` layer_id**: `0 = conv1`,
  `1 = conv2`, `2 = conv3`, `3 = conv4`, `4 = fc1`, `5 = fc2`.
  `manifest.json` stores this as `contract_layer_id` (plus the layer
  name as `contract_layer`), never as `wire_layer_id`.

## Driving compare_layers.py

Preferred: let `compare_layers.py` rebuild the references from the
dtype-correct feature (no `--ref` needed, `npu_forward` is bit-exact):

```powershell
python scripts/compare_layers.py reports/frames `
    --golden-feat reports/golden_ref/sine_440_full/feat.npy `
    --probs-encoding percent
```

If references must come from disk, map each wire layer to its file
(all paths below use `<stem>` = `sine_440_full`):

```powershell
python scripts/compare_layers.py reports/frames `
    --probs-encoding percent `
    --ref 0x00=reports/golden_ref/sine_440_full/feat.npy `
    --ref 0x01=reports/golden_ref/sine_440_full/conv1.npy `
    --ref 0x02=reports/golden_ref/sine_440_full/conv2.npy `
    --ref 0x03=reports/golden_ref/sine_440_full/conv3.npy `
    --ref 0x04=reports/golden_ref/sine_440_full/conv4.npy `
    --ref 0x05=reports/golden_ref/sine_440_full/fc1.npy `
    --ref 0x06=reports/golden_ref/sine_440_full/fc2_logits.npy `
    --ref 0x07=reports/golden_ref/sine_440_full/probs_u8_percent.npy
```

With `--probs-encoding q0.8` use
`--ref 0x07=.../probs_u8_q0_8.npy` instead. Layer 0x08 (STATS) has no
golden reference and is reported as skipped.

## Verification

```powershell
python scripts/gen_golden_refs.py
python -m pytest tests/test_golden_refs.py -q
```

The test re-runs `run_mel_pipeline` + `npu_forward` for every generated
stem and requires element-wise equality for all stage files (the only
narrowing allowed is int64 -> int32 for `gap`, bounded by 255). It also
checks that `probs` is within 0..65535 with `sum` inside
`65536 +/- 8` (each of the 8 classes may lose < 1 LSB; a dominant class
saturates at 65535, e.g. `sine_440_full` sums to 65535 and the
multi-class silence sample to 65537), that
`fc2_logits == fc2_u8 - 57`, and that every integer file yields
`max_abs_delta == 0` when fed back through `compare_layers.compare_array`
as a wire reference.
